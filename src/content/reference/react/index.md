Справочная документация React разделена на функциональные подразделы:

## React {/*react*/}

Программные возможности React:

* [Хуки](/reference/react/hooks) - Используйте различные возможности React из ваших компонентов.
* [Компоненты](/reference/react/components) - Встроенные компоненты, которые вы можете использовать в своем JSX.
* [API](/reference/react/apis) - API, полезные для определения компонентов.
* [Директивы](/reference/rsc/directives) - Предоставляют инструкции для сборщиков, совместимых с React Server Components.

## React DOM {/*react-dom*/}

`react-dom` содержит возможности, поддерживаемые только для веб-приложений (которые работают в среде браузерного DOM). Этот раздел разбит на следующие части:

* [Хуки](/reference/react-dom/hooks) - Хуки для веб-приложений, работающих в среде браузерного DOM.
* [Компоненты](/reference/react-dom/components) - React поддерживает все встроенные в браузер HTML и SVG компоненты.
* [API](/reference/react-dom) - Пакет `react-dom` содержит методы, поддерживаемые только в веб-приложениях.
* [Клиентские API](/reference/react-dom/client) - API `react-dom/client` позволяют рендерить компоненты React на клиенте (в браузере).
* [Серверные API](/reference/react-dom/server) - API `react-dom/server` позволяют рендерить компоненты React в HTML на сервере.

## Правила React {/*rules-of-react*/}

React имеет идиомы — или правила — о том, как выражать паттерны таким образом, чтобы их было легко понять и они приводили к созданию высококачественных приложений:

* [Компоненты и хуки должны быть чистыми](/reference/rules/components-and-hooks-must-be-pure) – Чистота делает ваш код более понятным, облегчает отладку и позволяет React автоматически правильно оптимизировать ваши компоненты и хуки.
* [React вызывает компоненты и хуки](/reference/rules/react-calls-components-and-hooks) – React отвечает за рендеринг компонентов и хуков при необходимости для оптимизации пользовательского опыта.
* [Правила хуков](/reference/rules/rules-of-hooks) – Хуки определяются с использованием функций JavaScript, но они представляют собой особый тип повторно используемой логики пользовательского интерфейса с ограничениями на то, где они могут быть вызваны.
