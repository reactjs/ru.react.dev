На [React Conf 2024](/blog/2024/05/22/react-conf-2024-recap) мы анонсировали экспериментальный выпуск React Compiler — инструмента сборки, который оптимизирует ваше React-приложение с помощью автоматической мемоизации. [Введение в React Compiler можно найти здесь](/learn/react-compiler).

С момента первого выпуска мы исправили многочисленные ошибки, о которых сообщало сообщество React, получили несколько высококачественных исправлений ошибок и внесли вклад[^1] в компилятор, сделали компилятор более устойчивым к широкому разнообразию шаблонов JavaScript и продолжили более широкое внедрение компилятора в Meta.

В этом посте мы хотим поделиться планами на будущее React Compiler.

## Попробуйте React Compiler Beta сегодня {/*try-react-compiler-beta-today*/}

На [React India 2024](https://www.youtube.com/watch?v=qd5yk2gxbtg) мы поделились обновлением о React Compiler. Сегодня мы рады анонсировать новый бета-выпуск React Compiler и плагина ESLint. Новые бета-версии публикуются в npm с тегом `@beta`.

Чтобы установить React Compiler Beta:

<TerminalBlock>
npm install -D babel-plugin-react-compiler@beta eslint-plugin-react-compiler@beta
</TerminalBlock>

Или, если вы используете Yarn:

<TerminalBlock>
yarn add -D babel-plugin-react-compiler@beta eslint-plugin-react-compiler@beta
</TerminalBlock>

Вы можете посмотреть выступление [Sathya Gunasekaran](https://twitter.com/_gsathya) на React India здесь:

<YouTubeIframe src="https://www.youtube.com/embed/qd5yk2gxbtg" />

## Мы рекомендуем всем использовать линтер React Compiler сегодня {/*we-recommend-everyone-use-the-react-compiler-linter-today*/}

Плагин ESLint для React Compiler помогает разработчикам проактивно выявлять и исправлять нарушения [Правил React](/reference/rules). **Мы настоятельно рекомендуем всем использовать линтер уже сегодня**. Линтер не требует установки компилятора, поэтому вы можете использовать его независимо, даже если вы еще не готовы попробовать компилятор.

Чтобы установить только линтер:

<TerminalBlock>
npm install -D eslint-plugin-react-compiler@beta
</TerminalBlock>

Или, если вы используете Yarn:

<TerminalBlock>
yarn add -D eslint-plugin-react-compiler@beta
</TerminalBlock>

После установки вы можете включить линтер, [добавив его в свою конфигурацию ESLint](/learn/react-compiler#installing-eslint-plugin-react-compiler). Использование линтера помогает выявлять нарушения Правил React, что облегчает внедрение компилятора после его полного выпуска.

## Обратная совместимость {/*backwards-compatibility*/}

React Compiler генерирует код, который зависит от API времени выполнения, добавленных в React 19, но с тех пор мы добавили поддержку компилятора для работы с React 17 и 18. Если вы еще не используете React 19, в бета-выпуске вы теперь можете попробовать React Compiler, указав минимальную `target` в конфигурации компилятора и добавив `react-compiler-runtime` в качестве зависимости. [Документацию по этому вопросу можно найти здесь](/learn/react-compiler#using-react-compiler-with-react-17-or-18).

## Использование React Compiler в библиотеках {/*using-react-compiler-in-libraries*/}

Наш первоначальный выпуск был сосредоточен на выявлении основных проблем с использованием компилятора в приложениях. С тех пор мы получили отличные отзывы и значительно улучшили компилятор. Теперь мы готовы к широкому обсуждению с сообществом, и авторы библиотек могут опробовать компилятор для повышения производительности и улучшения опыта разработки при поддержке своих библиотек.

React Compiler также может использоваться для компиляции библиотек. Поскольку React Compiler должен работать с исходным кодом до любых преобразований кода, конвейер сборки приложения не может компилировать используемые им библиотеки. Следовательно, мы рекомендуем сопровождающим библиотек самостоятельно компилировать и тестировать свои библиотеки с помощью компилятора и публиковать скомпилированный код в npm.

Поскольку ваш код будет предварительно скомпилирован, пользователям вашей библиотеки не потребуется включать компилятор, чтобы воспользоваться преимуществами автоматической мемоизации, примененной к вашей библиотеке. Если ваша библиотека ориентирована на приложения, которые еще не используют React 19, укажите минимальную `target` и добавьте `react-compiler-runtime` в качестве прямой зависимости. Пакет времени выполнения будет использовать правильную реализацию API в зависимости от версии приложения и при необходимости предоставит полифиллы для отсутствующих API.

[Дополнительную документацию по этому вопросу можно найти здесь.](/learn/react-compiler#using-the-compiler-on-libraries)

## Открытие Рабочей группы по React Compiler для всех {/*opening-up-react-compiler-working-group-to-everyone*/}

Ранее мы анонсировали закрытую [Рабочую группу по React Compiler](https://github.com/reactwg/react-compiler) на React Conf для предоставления обратной связи, вопросов и сотрудничества по экспериментальному выпуску компилятора.

С сегодняшнего дня, вместе с бета-выпуском React Compiler, мы открываем членство в Рабочей группе для всех. Цель Рабочей группы по React Compiler — подготовить экосистему к плавному, постепенному внедрению React Compiler в существующие приложения и библиотеки. Пожалуйста, продолжайте сообщать об ошибках в [репозитории React](https://github.com/facebook/react), но оставляйте отзывы, задавайте вопросы или делитесь идеями в [форуме обсуждений Рабочей группы](https://github.com/reactwg/react-compiler/discussions).

Основная команда также будет использовать репозиторий обсуждений для публикации результатов своих исследований. По мере приближения стабильного выпуска вся важная информация будет также публиковаться на этом форуме.

## React Compiler в Meta {/*react-compiler-at-meta*/}

На [React Conf](/blog/2024/05/22/react-conf-2024-recap) мы сообщили об успешном внедрении компилятора в Quest Store и Instagram. С тех пор мы развернули React Compiler в нескольких других крупных веб-приложениях в Meta, включая [Facebook](https://www.facebook.com) и [Threads](https://www.threads.net). Это означает, что если вы недавно пользовались любым из этих приложений, ваш опыт мог быть обеспечен работой компилятора. Нам удалось внедрить компилятор в эти приложения с минимальными изменениями кода, в монорепозитории с более чем 100 000 React-компонентов.

Мы наблюдали заметное повышение производительности во всех этих приложениях. По мере развертывания мы продолжаем видеть результаты, сопоставимые с [улучшениями, которыми мы ранее делились на ReactConf](https://youtu.be/lyEKhv8-3n0?t=3223). Эти приложения уже были тщательно настроены и оптимизированы инженерами Meta и экспертами React на протяжении многих лет, поэтому даже улучшения на несколько процентов являются для нас огромной победой.

Мы также ожидали повышения производительности разработчиков от React Compiler. Чтобы измерить это, мы сотрудничали с нашими партнерами по науке о данных в Meta[^2] для проведения тщательного статистического анализа влияния ручной мемоизации на производительность. Перед развертыванием компилятора в Meta мы обнаружили, что только около 8% pull-запросов React использовали ручную мемоизацию, и на создание этих pull-запросов уходило на 31-46% больше времени[^3]. Это подтвердило наше предположение о том, что ручная мемоизация создает когнитивную нагрузку, и мы ожидаем, что React Compiler приведет к более эффективному написанию и проверке кода. Примечательно, что React Compiler также гарантирует, что *весь* код мемоизируется по умолчанию, а не только те 8% (в нашем случае), где разработчики явно применяют мемоизацию.

## Дорожная карта к стабильной версии {/*roadmap-to-stable*/}

*Это не окончательная дорожная карта, и она может быть изменена.*

Мы намерены выпустить Release Candidate компилятора в ближайшем будущем после бета-выпуска, когда будет доказано, что большинство приложений и библиотек, следующих Правилам React, хорошо работают с компилятором. После периода окончательной обратной связи от сообщества мы планируем выпустить стабильную версию компилятора. Стабильный выпуск ознаменует начало нового фундамента для React, и всем приложениям и библиотекам будет настоятельно рекомендовано использовать компилятор и плагин ESLint.

* ✅ Экспериментальный: Выпущен на React Conf 2024, в основном для получения отзывов от ранних пользователей.
* ✅ Публичная бета-версия: Доступна сегодня для получения отзывов от более широкого сообщества.
* 🚧 Release Candidate (RC): React Compiler работает для большинства приложений и библиотек, следующих правилам, без проблем.
* 🚧 Общая доступность: После периода окончательной обратной связи от сообщества.

Эти выпуски также включают плагин ESLint для компилятора, который отображает диагностику, статически проанализированную компилятором. Мы планируем объединить существующий плагин `eslint-plugin-react-hooks` с плагином ESLint компилятора, чтобы требовалась установка только одного плагина.

После стабильного выпуска мы планируем добавить больше оптимизаций и улучшений компилятора. Это включает как постоянные улучшения автоматической мемоизации, так и совершенно новые оптимизации, с минимальными изменениями кода продукта или без них. Обновление до каждого нового выпуска компилятора должно быть простым, и каждое обновление будет продолжать улучшать производительность и обеспечивать лучшую обработку разнообразных шаблонов JavaScript и React.

На протяжении всего этого процесса мы также планируем прототипировать расширение IDE для React. Это все еще очень ранний этап исследований, поэтому мы ожидаем, что сможем поделиться более подробной информацией в будущих публикациях в блоге React Labs.
