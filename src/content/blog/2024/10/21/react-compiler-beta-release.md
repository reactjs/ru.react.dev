На [React Conf 2024](/blog/2024/05/22/react-conf-2024-recap) мы анонсировали экспериментальную версию React Compiler, инструмента времени сборки, который оптимизирует ваше React-приложение посредством автоматической мемоизации. [Здесь вы можете найти введение в React Compiler](/learn/react-compiler).

С момента первого выпуска мы исправили многочисленные ошибки, о которых сообщило сообщество React, получили несколько высококачественных исправлений ошибок и внесли вклад[^1] в компилятор, сделали компилятор более устойчивым к широкому разнообразию шаблонов JavaScript и продолжили более широкое развертывание компилятора в Meta.

В этой статье мы хотим поделиться информацией о дальнейших планах для React Compiler.

## Попробуйте бета-версию React Compiler сегодня {/*try-react-compiler-beta-today*/}

На [React India 2024](https://www.youtube.com/watch?v=qd5yk2gxbtg) мы поделились информацией об обновлении React Compiler. Сегодня мы рады объявить о новом бета-выпуске React Compiler и плагина ESLint. Новые бета-версии публикуются в npm с использованием тега `@beta`.

Чтобы установить бета-версию React Compiler:

<TerminalBlock>
npm install -D babel-plugin-react-compiler@beta eslint-plugin-react-compiler@beta
</TerminalBlock>

Или, если вы используете Yarn:

<TerminalBlock>
yarn add -D babel-plugin-react-compiler@beta eslint-plugin-react-compiler@beta
</TerminalBlock>

Вы можете посмотреть выступление [Сатьи Гунасекарана](https://twitter.com/_gsathya) на React India здесь:

<YouTubeIframe src="https://www.youtube.com/embed/qd5yk2gxbtg" />

## Мы рекомендуем всем использовать линтер React Compiler сегодня {/*we-recommend-everyone-use-the-react-compiler-linter-today*/}

Плагин ESLint React Compiler помогает разработчикам упреждающе выявлять и исправлять нарушения [Правил React](/reference/rules). **Мы настоятельно рекомендуем всем использовать линтер сегодня**. Для работы линтера не требуется, чтобы у вас был установлен компилятор, поэтому вы можете использовать его независимо, даже если вы не готовы попробовать компилятор.

Чтобы установить только линтер:

<TerminalBlock>
npm install -D eslint-plugin-react-compiler@beta
</TerminalBlock>

Или, если вы используете Yarn:

<TerminalBlock>
yarn add -D eslint-plugin-react-compiler@beta
</TerminalBlock>

После установки вы можете включить линтер, [добавив его в конфигурацию ESLint](/learn/react-compiler#installing-eslint-plugin-react-compiler). Использование линтера помогает выявлять нарушения Правил React, упрощая внедрение компилятора после его полного выпуска.

## Обратная совместимость {/*backwards-compatibility*/}

React Compiler создает код, который зависит от API среды выполнения, добавленных в React 19, но с тех пор мы добавили поддержку работы компилятора с React 17 и 18. Если вы еще не используете React 19, в бета-версии вы теперь можете попробовать React Compiler, указав минимальный `target` в конфигурации компилятора и добавив `react-compiler-runtime` в качестве зависимости. [Вы можете найти документацию по этому вопросу здесь](/learn/react-compiler#using-react-compiler-with-react-17-or-18).

## Использование React Compiler в библиотеках {/*using-react-compiler-in-libraries*/}

Наш первоначальный выпуск был сосредоточен на выявлении основных проблем при использовании компилятора в приложениях. Мы получили отличную обратную связь и с тех пор существенно улучшили компилятор. Теперь мы готовы к широкой обратной связи от сообщества и к тому, чтобы авторы библиотек попробовали компилятор для повышения производительности и улучшения опыта разработчиков при обслуживании вашей библиотеки.

React Compiler также можно использовать для компиляции библиотек. Поскольку React Compiler должен запускаться на исходном коде до каких-либо преобразований кода, конвейер сборки приложения не может компилировать используемые им библиотеки. Следовательно, мы рекомендуем разработчикам библиотек независимо компилировать и тестировать свои библиотеки с помощью компилятора и поставлять скомпилированный код в npm.

Поскольку ваш код предварительно скомпилирован, пользователям вашей библиотеки не нужно будет включать компилятор, чтобы воспользоваться преимуществами автоматической мемоизации, применяемой к вашей библиотеке. Если ваша библиотека предназначена для приложений, которые еще не используют React 19, укажите минимальный `target` и добавьте `react-compiler-runtime` в качестве прямой зависимости. Пакет среды выполнения будет использовать правильную реализацию API в зависимости от версии приложения и при необходимости полифилить отсутствующие API.

[Вы можете найти больше документации по этому вопросу здесь.](/learn/react-compiler#using-the-compiler-on-libraries)

## Открытие Рабочей группы React Compiler для всех {/*opening-up-react-compiler-working-group-to-everyone*/}

Ранее мы анонсировали Рабочую группу React Compiler [только по приглашениям](https://github.com/reactwg/react-compiler) на React Conf, чтобы предоставить обратную связь, задать вопросы и сотрудничать над экспериментальным выпуском компилятора.

С сегодняшнего дня, вместе с бета-версией React Compiler, мы открываем членство в Рабочей группе для всех. Цель Рабочей группы React Compiler — подготовить экосистему к плавному, постепенному внедрению React Compiler существующими приложениями и библиотеками. Пожалуйста, продолжайте сообщать об ошибках в [репозитории React](https://github.com/facebook/react), но, пожалуйста, оставляйте отзывы, задавайте вопросы или делитесь идеями на [форуме обсуждений Рабочей группы](https://github.com/reactwg/react-compiler/discussions).

Основная команда также будет использовать репозиторий обсуждений для обмена результатами наших исследований. По мере приближения стабильного выпуска любая важная информация также будет размещена на этом форуме.

## React Compiler в Meta {/*react-compiler-at-meta*/}

На [React Conf](/blog/2024/05/22/react-conf-2024-recap) мы сообщили, что наше развертывание компилятора в Quest Store и Instagram было успешным. С тех пор мы развернули React Compiler в нескольких других крупных веб-приложениях в Meta, включая [Facebook](https://www.facebook.com) и [Threads](https://www.threads.net). Это означает, что если вы недавно использовали какое-либо из этих приложений, ваш опыт, возможно, был обеспечен компилятором. Мы смогли внедрить эти приложения в компилятор с небольшим количеством изменений кода, в монорепозитории с более чем 100 000 React-компонентов.

Мы наблюдаем заметное повышение производительности во всех этих приложениях. По мере развертывания мы продолжаем видеть результаты порядка [выигрышей, которыми мы поделились ранее на ReactConf](https://youtu.be/lyEKhv8-3n0?t=3223). Эти приложения уже были тщательно настроены и оптимизированы инженерами Meta и экспертами React за эти годы, поэтому даже улучшения порядка нескольких процентов — огромный выигрыш для нас.

Мы также ожидали выигрышей в производительности разработчиков от React Compiler. Чтобы измерить это, мы сотрудничали с нашими партнерами по науке о данных в Meta[^2], чтобы провести тщательный статистический анализ влияния ручной мемоизации на производительность. До развертывания компилятора в Meta мы обнаружили, что только около 8% pull requests React использовали ручную мемоизацию и что эти pull requests занимали на 31–46% больше времени на создание[^3]. Это подтвердило нашу интуицию о том, что ручная мемоизация вносит когнитивные издержки, и мы ожидаем, что React Compiler приведет к более эффективному написанию и рецензированию кода. Примечательно, что React Compiler также гарантирует, что *весь* код мемоизируется по умолчанию, а не только (в нашем случае) 8%, где разработчики явно применяют мемоизацию.

## План разработки до стабильного выпуска {/*roadmap-to-stable*/}

*Это не окончательный план разработки, и он может быть изменен.*

Мы намерены выпустить Release Candidate компилятора в ближайшем будущем после бета-выпуска, когда будет доказано, что большинство приложений и библиотек, которые следуют Правилам React, хорошо работают с компилятором. После периода окончательной обратной связи от сообщества мы планируем стабильный выпуск компилятора. Стабильный выпуск ознаменует начало новой основы для React, и всем приложениям и библиотекам будет настоятельно рекомендовано использовать компилятор и плагин ESLint.

* ✅ Экспериментальный: выпущен на React Conf 2024, в основном для обратной связи от первых пользователей.
* ✅ Публичная бета-версия: доступна сегодня для обратной связи от более широкого сообщества.
* 🚧 Release Candidate (RC): React Compiler работает для большинства приложений и библиотек, соответствующих правилам, без проблем.
* 🚧 Общая доступность: после периода окончательной обратной связи от сообщества.

Эти выпуски также включают плагин ESLint компилятора, который отображает диагностику, статически проанализированную компилятором. Мы планируем объединить существующий плагин eslint-plugin-react-hooks с плагином ESLint компилятора, поэтому необходимо установить только один плагин.

После стабильного выпуска мы планируем добавить больше оптимизаций и улучшений компилятора. Это включает в себя как постоянные улучшения автоматической мемоизации, так и совершенно новые оптимизации, с минимальным изменением кода продукта или без него. Обновление до каждого нового выпуска компилятора должно быть простым, и каждое обновление будет продолжать улучшать производительность и добавлять лучшую обработку разнообразных шаблонов JavaScript и React.

В течение этого процесса мы также планируем создать прототип расширения IDE для React. Пока это очень ранние исследования, поэтому мы ожидаем, что сможем поделиться с вами дополнительными результатами в будущей статье блога React Labs.
