[React Compiler](https://react.dev/learn/react-compiler) — это инструмент времени сборки, который оптимизирует ваше React-приложение посредством автоматической мемоизации. В прошлом году мы опубликовали [первую бета-версию](https://react.dev/blog/2024/10/21/react-compiler-beta-release) React Compiler и получили много отличных отзывов и вкладов. Мы рады успехам, которые мы увидели от людей, использующих компилятор (см. примеры из [Sanity Studio](https://github.com/reactwg/react-compiler/discussions/33) и [Wakelet](https://github.com/reactwg/react-compiler/discussions/52)), и работаем над стабильным выпуском.

Сегодня мы выпускаем первый кандидат на выпуск (RC) компилятора. RC предназначен для того, чтобы быть стабильной и почти окончательной версией компилятора, которую можно безопасно опробовать в продакшене.

## Используйте React Compiler RC сегодня {/*use-react-compiler-rc-today*/}
Чтобы установить RC:

npm
<TerminalBlock>
{`npm install --save-dev --save-exact babel-plugin-react-compiler@rc`}
</TerminalBlock>

pnpm
<TerminalBlock>
{`pnpm add --save-dev --save-exact babel-plugin-react-compiler@rc`}
</TerminalBlock>

yarn
<TerminalBlock>
{`yarn add --dev --exact babel-plugin-react-compiler@rc`}
</TerminalBlock>

В рамках RC мы упростили добавление React Compiler в ваши проекты и добавили оптимизации в способ, которым компилятор генерирует мемоизацию. React Complier теперь поддерживает необязательные цепочки и индексы массивов в качестве зависимостей. Мы изучаем, как выводить еще больше зависимостей, таких как проверки на равенство и интерполяция строк. Эти улучшения в конечном итоге приводят к меньшему количеству перерендеров и более отзывчивым пользовательским интерфейсам.

Мы также услышали от сообщества, что проверка ref-in-render иногда выдает ложные срабатывания. Поскольку в качестве общей философии мы хотим, чтобы вы могли полностью доверять сообщениям об ошибках и подсказкам компилятора, мы отключаем ее по умолчанию на данный момент. Мы продолжим работать над улучшением этой проверки и повторно включим ее в последующем выпуске.

Вы можете найти более подробную информацию об использовании Compiler в [нашей документации](https://react.dev/learn/react-compiler).

## Обратная совместимость {/*backwards-compatibility*/}
Как отмечалось в объявлении Beta, React Compiler совместим с React 17 и выше. Если вы еще не используете React 19, вы можете использовать React Compiler, указав минимальную цель в конфигурации вашего компилятора и добавив `react-compiler-runtime` в качестве зависимости. Вы можете найти документацию по этому вопросу [здесь](https://react.dev/learn/react-compiler#using-react-compiler-with-react-17-or-18).

## Миграция с eslint-plugin-react-compiler на eslint-plugin-react-hooks {/*migrating-from-eslint-plugin-react-compiler-to-eslint-plugin-react-hooks*/}
Если вы уже установили eslint-plugin-react-compiler, теперь вы можете удалить его и использовать `eslint-plugin-react-hooks@6.0.0-rc.1`. Большое спасибо [@michaelfaith](https://bsky.app/profile/michael.faith) за вклад в это улучшение!

Для установки:

npm
<TerminalBlock>
{`npm install --save-dev eslint-plugin-react-hooks@6.0.0-rc.1`}
</TerminalBlock>

pnpm
<TerminalBlock>
{`pnpm add --save-dev eslint-plugin-react-hooks@6.0.0-rc.1`}
</TerminalBlock>

yarn
<TerminalBlock>
{`yarn add --dev eslint-plugin-react-hooks@6.0.0-rc.1`}
</TerminalBlock>

```js
// eslint.config.js
import * as reactHooks from 'eslint-plugin-react-hooks';

export default [
  // Flat Config (eslint 9+)
  reactHooks.configs.recommended,

  // Legacy Config
  reactHooks.configs['recommended-latest']
];
```

Чтобы включить правило React Compiler, добавьте `'react-hooks/react-compiler': 'error'` в вашу конфигурацию ESLint.

Линтер не требует установки компилятора, поэтому нет риска при обновлении eslint-plugin-react-hooks. Мы рекомендуем всем обновиться сегодня.

## Поддержка swc (экспериментальная) {/*swc-support-experimental*/}
React Compiler можно установить в [несколько инструментов сборки](/learn/react-compiler#installation), таких как Babel, Vite и Rsbuild.

В дополнение к этим инструментам мы сотрудничаем с Кангом Донгюном ([@kdy1dev](https://x.com/kdy1dev)) из команды [swc](https://swc.rs/) над добавлением дополнительной поддержки React Compiler в качестве плагина swc. Хотя эта работа не завершена, производительность сборки Next.js теперь должна быть значительно быстрее, когда [React Compiler включен в вашем приложении Next.js](https://nextjs.org/docs/app/api-reference/config/next-config-js/reactCompiler).

Мы рекомендуем использовать Next.js [15.3.1](https://github.com/vercel/next.js/releases/tag/v15.3.1) или выше, чтобы получить наилучшую производительность сборки.

Пользователи Vite могут продолжать использовать [vite-plugin-react](https://github.com/vitejs/vite-plugin-react) для включения компилятора, добавив его в качестве [плагина Babel](https://react.dev/learn/react-compiler#usage-with-vite). Мы также работаем с командой [oxc](https://oxc.rs/) над [добавлением поддержки компилятора](https://github.com/oxc-project/oxc/issues/10048). Как только [rolldown](https://github.com/rolldown/rolldown) будет официально выпущен и поддержан в Vite, а также будет добавлена поддержка oxc для React Compiler, мы обновим документацию информацией о том, как выполнить миграцию.

## Обновление React Compiler {/*upgrading-react-compiler*/}
React Compiler работает лучше всего, когда применяемая автоматическая мемоизация предназначена строго для производительности. Будущие версии компилятора могут изменить способ применения мемоизации, например, она может стать более детальной и точной.

Однако, поскольку код продукта иногда может нарушать [правила React](https://react.dev/reference/rules) способами, которые не всегда можно статически обнаружить в JavaScript, изменение мемоизации иногда может приводить к неожиданным результатам. Например, ранее мемоизированное значение может использоваться в качестве зависимости для useEffect где-то в дереве компонентов. Изменение способа или того, будет ли это значение мемоизировано, может привести к чрезмерному или недостаточному срабатыванию этого useEffect. Хотя мы рекомендуем [использовать useEffect только для синхронизации](https://react.dev/learn/synchronizing-with-effects), ваша кодовая база может иметь useEffects, которые охватывают другие варианты использования, такие как эффекты, которые должны запускаться только в ответ на изменение определенных значений.

Другими словами, изменение мемоизации при редких обстоятельствах может привести к неожиданному поведению. По этой причине мы рекомендуем следовать Правилам React и использовать непрерывное сквозное тестирование вашего приложения, чтобы вы могли уверенно обновлять компилятор и выявлять любые нарушения правил React, которые могут вызвать проблемы.

Если у вас нет хорошего покрытия тестами, мы рекомендуем зафиксировать компилятор на точной версии (например, `19.1.0`), а не на диапазоне SemVer (например, `^19.1.0`). Вы можете сделать это, передав флаги `--save-exact` (npm/pnpm) или `--exact` (yarn) при обновлении компилятора. Затем вы должны выполнять любые обновления компилятора вручную, заботясь о том, чтобы проверить, что ваше приложение по-прежнему работает должным образом.

## Дорожная карта к стабильному выпуску {/*roadmap-to-stable*/}
*Это не окончательная дорожная карта, и она может быть изменена.*

После периода окончательной обратной связи от сообщества по RC мы планируем стабильный выпуск компилятора.

* ✅ Экспериментальный: выпущен на React Conf 2024, в основном для обратной связи от разработчиков приложений.
* ✅ Публичная бета-версия: доступна сегодня для обратной связи от авторов библиотек.
* ✅ Кандидат на выпуск (RC): React Compiler работает для большинства приложений и библиотек, соблюдающих правила, без проблем.
* Общая доступность: после периода окончательной обратной связи от сообщества.

После стабильного выпуска мы планируем добавить больше оптимизаций и улучшений компилятора. Это включает в себя как постоянные улучшения автоматической мемоизации, так и новые оптимизации в целом, с минимальным изменением кода продукта или без него. Каждое обновление будет продолжать улучшать производительность и добавлять лучшую обработку различных шаблонов JavaScript и React.
